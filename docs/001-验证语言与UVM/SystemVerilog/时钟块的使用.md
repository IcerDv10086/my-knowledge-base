# SystemVerilog 时钟块（clocking block）使用指南

## 1. 为什么要用时钟块

时钟块的核心价值是把“采样时机、驱动时机、信号方向”显式化，减少 TB 与 DUT 交互时的 race condition。

典型收益：

- 同步关系更清晰。
- 采样/驱动相位可统一配置。
- 多接口场景更易维护。

## 2. 基本语法

```systemverilog
clocking cb @(posedge clk);
  default input #1step output #0;
  input  req, gnt;
  output addr, data;
endclocking
```

关键点：

- `@(posedge clk)`：定义时钟事件。
- `input/output/inout`：定义时钟变量方向。
- `#skew`：定义采样/驱动偏斜。

## 3. 偏斜（skew）规则

- 默认：`input #1step`、`output #0`。
- `input #1step`：通常采样上一个稳定点，减少竞争。
- `input #0`：在 Observed 区域采样。
- `output #0`：在 Re-NBA 区域驱动。

工程建议：

- 优先使用默认偏斜；只有明确需要才改偏斜。
- 采样端避免与 DUT 同时驱动。

## 4. 常用机制

### 4.1 默认时钟

同一作用域可定义一个 `default clocking`，供 `##N` 周期延迟使用。

### 4.2 周期延迟

- `##N` 表示相对默认时钟延迟 N 个周期。
- `##0` 语义依赖当前时间片是否已触发时钟事件。

### 4.3 同步驱动

```systemverilog
cb.addr <= ##1 next_addr;
```

其语义与普通 NBA 类似但不等价，受时钟块相位与偏斜约束。

## 5. 多时钟块与接口配合

- 同一信号可出现在多个时钟块，但应避免语义冲突。
- 推荐把时钟块放在 interface 内，并通过 modport 暴露给 driver/monitor。

## 6. 常见错误

1. 在 monitor 中直接 `@(posedge clk)` 采样，忽略 clocking block，导致竞态。
2. output 变量被多个进程在同周期驱动，覆盖关系不清。
3. `inout` 信号既当采样又当驱动，未明确职责边界。

## 7. 最佳实践

- TB 驱动统一走 clocking block。
- monitor 采样统一走 clocking block 的 `input`。
- 每个接口至少定义一个“官方时钟块”，避免各自为政。
