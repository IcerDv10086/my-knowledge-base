# CDC、RDC 和 STA 检查总结

## 文档目的

站在验证角度，梳理 CDC（Clock Domain Crossing，时钟域交叉）、RDC（Reset Domain Crossing，复位域交叉）和 STA（Static Timing Analysis，静态时序分析）检查的基本原理，理解时序问题成因并探索解决方式。

## 工具基本原理

### 芯片设计流程

CDC 检查、静态时序分析是设计侧进行 sign-off 的主要依据。

### SDC 约束文件

SDC（Synopsys Design Constraints）约束文件是芯片设计中的时序约束文件，常见内容分为四类：

**时钟约束：**

| 约束类型 | 命令示例 | 说明 |
| :--- | :--- | :--- |
| 主时钟 | `create_clock` | 定义芯片主时钟源 |
| 生成时钟 | `create_generated_clock` | 由主时钟分频或倍频产生的时钟 |
| 时钟不确定性 | `set_clock_uncertainty` | 定义时钟抖动和偏斜预算 |

**IO 输入输出延迟约束：**

| 约束类型 | 命令示例 | 说明 |
| :--- | :--- | :--- |
| 输入延迟 | `set_input_delay` | 外部路径已消耗时间 |
| 输出延迟 | `set_output_delay` | 芯片输出到外部采样点的预算 |

**时序例外约束：**  

| 约束类型 | 命令示例 | 说明 |
| :--- | :--- | :--- |
| 伪路径 | `set_false_path` | 不参与时序收敛的路径，常见于异步跨域 |
| 多周期路径 | `set_multicycle_path` | 允许跨多个时钟周期完成传输的功能路径 |
| 异步时钟组 | `set_clock_groups -asynchronous` | 声明时钟域间无固定相位关系 |

**工作环境约束：**

- 工艺角、电压、温度（PVT）
- 负载、驱动、设计规则类约束

**关键点**：SDC 本质是告诉工具"哪些路径该查、按什么标准查、哪些路径不该查"。约束错误会直接导致"假违例"或"漏违例"。

 与后续工具的关系

| 工具类型 | 依赖约束 | 判断依据 |
| :--- | :--- | :--- |
| CDC/RDC 工具 | 时钟、复位和模式约束 | 是否跨域 |
| STA 工具 | 时钟、IO、例外约束 | 是否违例 |

**约束先验错误会在三类检查中被放大**，因此先做约束体检再跑签核更高效。

### CDC 检查

**常用工具**: SpyGlass CDC（或同类工具）

**核心目标**:

1. 识别跨时钟域数据路径
2. 检查同步结构是否完整（如双触发器同步、握手、异步 FIFO 等）
3. 发现潜在亚稳态传播风险

**验证视角关注点**:

不是只看"有无 CDC 报告"，而是看"每条跨域路径是否匹配其预期同步方案"。

**工具使用原理（验证侧）:**

   | 步骤 | 说明 |
   | :--- | :--- |
   | 抽象建模 | 工具根据时钟定义和网表连接建立时钟域关系图 |
   | 结构识别 | 基于规则库识别同步器、握手、异步 FIFO 等已知安全结构 |
   | 风险归类 | 对未识别保护结构的跨域路径打规则标签并分级告警 |
   | 报告收敛 | 通过约束、白名单和结构修正逐步减少噪声告警 |

### RDC 检查

**核心概念**:

RDC（Reset Domain Crossing，复位域交叉）关注异步控制信号跨域问题。常见异步控制端包括：`reset`、`preset`、`set`、`clear`。

**典型风险**:

1. 同源异步控制在不同域释放不同步
2. 异步复位释放后局部电路先后启动，导致暂态错误
3. 复位树/门控逻辑引入不可预期时序窗口

**工具使用原理（验证侧）**:

| 步骤 | 说明 |
| :--- | :--- |
| 域定义 | 工具先识别各触发器受哪一路复位/控制信号支配 |
| 传播分析 | 沿控制网络追踪异步信号传播与扇出范围 |
| 释放一致性检查 | 检查同一功能链路上相关寄存器是否满足同步释放策略 |
| 误报控制 | 用复位意图约束和设计注释区分"设计允许"与"真实风险" |

### STA 检查

**常用工具**: PrimeTime（或同类时序签核工具）

**核心思想**:

1. 以时钟定义的起点触发器和终点触发器为分析对象
2. 计算最大延迟（setup）与最小延迟（hold）
3. 在给定约束和工艺角下判断是否满足时序

**注意事项**:

1. STA 主要分析同步时序路径
2. 对异步关系通常通过 `set_false_path` 或 `set_clock_groups -asynchronous` 排除
3. 被排除的路径不会被 STA 检查，因此 CDC/RDC 必须兜底

**工具使用原理（验证侧）**:

| 步骤 | 说明 |
| :--- | :--- |
| 时序图展开 | 工具按时钟关系把网表展开为起点→组合逻辑→终点路径 |
| 延迟计算 | 在不同 PVT 角和寄生参数下计算数据到达时间与时钟到达时间 |
| 裕量评估 | setup 裕量 = 要求到达时间 - 实际到达时间；hold 裕量 = 实际最早到达时间 - 要求最早到达时间 |
| 违例定位 | 按路径组、时钟组、层级模块聚类，定位主要瓶颈路径 |
| 闭环修复 | 通过改约束、改结构、改物理实现三类手段迭代收敛 |
