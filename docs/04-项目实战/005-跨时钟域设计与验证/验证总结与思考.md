# 验证思考与总结

## 后仿验证必要性

在实际设计中完成这些工作后，一般仍需进行带 SDF 的后仿进行功能仿真，原因如下：

- STA 是数学证明，前提是**约束**和模型都对
    - 一旦约束漏了/错了（比如 generated clock、false path、multicycle 写错），STA 会"证明一个错误前提下的正确性"。后仿能以行为方式暴露这类问题。

- CDC/RDC 主要是结构/协议安全检查，不等于功能行为全覆盖
    - CDC/RDC 只是"跨域结构看起来安全"，但不保证具体时序下协议不会**死锁/丢脉冲**（尤其边界激励、门控、模式切换）。后仿可在真实门延时下观察这些边角行为。

- 后仿能看到 X 传播与初始化问题
    - RTL 常被乐观语义"掩盖"。网表仿真里**未复位寄存器、RAM 初值、X 扩散**会更真实，能提前发现上电/复位序列问题。

- 能验证工艺库/网表集成层面的"实现问题"
    - SDF 回标是否正确、库模型是否匹配、时序检查器（setup/hold/recovery/removal）是否按预期触发
    - 时钟门控单元、组合反馈、脉冲吞噬这类实现细节更容易在后仿暴露

- DFT/低功耗/多模式切换常依赖后仿兜底
    - scan shift/capture、test mode 时钟切换、UPF 的 isolation/retention 时序，很多团队会用后仿做签核前 sanity。

## 时序问题的验证方法论

验证发现 RTL 缺陷本质依赖"有效的随机激励 + 有效检查器 + 覆盖率检查"；对于 时序问题 检查同样如此。为了更高效地暴露时序相关问题，可把工作拆成三个阶段：

### 验证环境搭建

- 系统梳理时钟时钟源与复位树关系，在 RTL 输入时钟上按场景注入抖动、频偏，并按需调整占空比
- 明确时钟域切换时序，避免后续用例对时钟域复位假设不一致

### 前仿增强

- 复位场景：覆盖多复位信号交叉、先后释放、短脉冲释放等场景
- 脉冲计数，重点排查丢脉冲和重复采样问题
- xprop 检查 X 传播与初始化问题，确保在时钟域切换时，X 信号能正确传播(典型：寄存器未复位、SRAM未写入先读取)
- EOT 检查增强：风险模块的关键信号进行猴脸检查，激励最后避免无意义的清零和强制复位，降低死锁被覆盖的概率

> 通常复位信号由有效脉冲宽度要求，一般时对应时钟域下至少4个周期及以上。在多复位源场景下，需要通对应设计确认。

### 后仿强化

- 回归测试用例设置高优先级：按模块风险划分，识别常见异常模块，定义为风险模块并重点加固
- 亚稳态注入：如IO的同步器第一级触发器，在0-1个时钟周期内通过随机延迟的方式注入。
- glitch监测：建立通用glitch断言框架，监测IO口和关键异步路径上是否出现 glitch 毛刺。
- 后仿覆盖点分析：时序
