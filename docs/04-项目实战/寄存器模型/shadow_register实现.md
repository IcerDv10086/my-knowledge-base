# UVM shadow寄存器实现总结

## shadow寄存器概述

某项目内部总线结构中，控制模块内部存在地址偏移寄存器，用于输出高8位地址给总线控制模块。**新增shadow类型寄存器，用于实现特殊寄存器在控制模块与多个子模块间的快速访问。**

总线转换简化结构：串行接口 → 控制模块（8位/16位地址转换）→ 总线控制模块 → 多个子模块。

shadow寄存器分为master、slave两类：

- 两者均可通过物理实际地址总线访问
- 仅master模块存在寄存器字段（`uvm_reg_field`）实体，slave模块仅为地址映射，无实体
- master与slave寄存器字段支持1对1、1对多对应关系

## UVM寄存器模型实现思路

寄存器模型用于模拟设计寄存器，简化验证流程。本项目新增的shadow寄存器无法通过标准UVM寄存器生成，且存在镜像值与DUT不匹配问题，需对UVM源码进行拓展。

### 实现目标

1. 支持slave寄存器按UVM寄存器字段进行后门读写访问
2. 对任意master/slave寄存器执行后门读写时，同步更新master及所有关联slave寄存器
3. 禁止对slave寄存器执行非字段级后门读写，违规则报错并终止仿真
4. master与slave寄存器均支持正常前门读写操作
5. 后门访问slave的shadow寄存器时报错，普通寄存器可正常后门访问

### 实现说明

基于SystemVerilog语言实现UVM寄存器模型拓展，重写build等关键虚函数，完成寄存器模型构建与访问约束。

实现步骤：

1. 修改shadow寄存器的class的build函数，传入field类型，所有shadow寄存器都需要修改
2. 在block层级下，先声明一个shadow的寄存器域段，用作唯一的寄存器字段实体
3. 按照**先后顺序**，先添加至slave类型的shadow寄存器，最后添加至master类型的shadow寄存器
4. 重载`uvm_reg_backdoor`类，并修改write、read方法，当对slave类型的shadow寄存器操作时则报错

### 优化建议

1. 后续同事建议，不需要步骤4，因为它主要实现目标5，后门访问slave的shadow寄存器时报错。而目标5实际没有意义，直接访问亦是一种不错的选择，不需要报错处理。
2. 步骤1、2、3的修改可融入到寄存器脚本生成的脚本中。
3. 修改后寄存器扫描case处理时，不再需要对shadow寄存器做特殊处理，可以直接借助uvm自带的扫描sequence即可。
