# Pattern生成与反灌

## 生成

默认情况下，验证团队根据CP测试表格的测试点，生成**读写事件类型pattern**。CP团队将其转换成时序pattern格式和对应不同测试机台的配置文件。这里团队内部约定了一种转换格式。

为了方便复现，一般需要修改验证环境，并编写定向的测试用例：

- 定义打印宏开关，增加fp文件指针
- 重载读写函数，可以将指令打印到fp文件中
- 增加等待函数、IRQ检查函数、SHUTDOWN函数，操作时同样打印到fp文件中
- 编写测试用例，根据测试点，调用重载的读写函数、等待函数、IRQ检查函数、SHUTDOWN函数，将指令打印到fp文件中

测试点的编写原则：

- 一定要有checker，通常是状态寄存器、中断接口信号
- 简化配置，配置越短越好，每个pattern尽量避免覆写成默认配置

## 反灌

反灌的数据格式有两种，一种是时序pattern格式，另外一种是读写事件类型pattern格式。

对于读写事件类型的pattern格式，封装一个函数，逐行读取fp文件中的指令，根据指令的类型，调用对应的读写函数、等待函数、IRQ检查函数、SHUTDOWN函数。

对于时序pattern格式，首先需要弄明白每一个接口信号的每一个值对应的含义。然后封装一个函数，逐行读取fp文件中的指令，根据指令的类型，实现对应fp的时序。
