# 术语与风格规范

本文档用于统一知识库写作风格、术语口径与 Markdown 结构。新增或改写文档时，默认遵循本规范。

## 1. 术语规范

- RTL：寄存器传输级设计。
- TB：Testbench，验证平台。
- DUT：Design Under Test，被测设计。
- UVM：统一验证方法学（Unified Verification Methodology）。
- 前仿：功能仿真阶段，通常不关注精确门级时序。
- 后仿：门级/网表仿真阶段，关注 SDF 反标与时序一致性。
- 反标：将 SDF 延时信息加载到网表仿真中。
- 覆盖率：默认指功能覆盖率与代码覆盖率，需明确具体类型。

术语使用要求：

- 首次出现的英文缩写，建议补全中文含义。
- 同一文档内保持一种写法，不混用同义词（如“后仿/门级仿真”需固定主称谓）。
- 命令、路径、参数使用代码格式标注。

## 2. 文档结构规范

写作要求：

- 标题使用 `#`、`##`、`###` 的层级结构，不使用纯缩进模拟层级。
- 表格必须有表头；列表使用统一编号或无序列表；表格使用左对齐。
- 段落保持短句，避免一段过长。
- 尽量不要使用四级及以上标题。
- 一级标题不要使用序号表述顺序。
- 标题不要中英文混用，且尽可能简短，避免使用复杂的术语。
- 不要在段落间、主题内容间轻易使用`---`分割线，但建议如文档的最后参考文献、QA等场景前使用。

## 3. 代码与命令规范

- 单行命令使用行内代码，例如 `bsub -q normal -n 4`。
- 多行命令使用代码块并标注语言。
- 命令示例优先给可直接执行的最小闭环示例。
- 危险命令（例如 `rm -rf`）需附带风险提示。

## 4. 图表与图片规范

- 图片统一放在文档同级 `assets/` 或分类统一 `assets/` 目录。
- 本地引用优先，避免长期依赖外链。
- 图片命名建议使用英文小写和连字符，例如 `uvm-phase-order.png`。
- 若图片缺失，先保留占位说明：`TODO: 补图（来源/用途）`。

## 5. 风格规则

- 使用陈述句，避免口语化堆叠。
- 结论先行：先说“是什么/为什么”，再说“怎么做”。
- 对比类内容优先使用表格表达。

## 6. 质量自检清单

发布前至少检查以下项目：

- 标题层级是否正确。
- 术语是否统一。
- 命令是否可执行。
- 链接与图片路径是否有效。
- 是否包含可复现的最小示例。

## 7. 常见问题与排查

### 7.1 表格格式问题

表格分隔符行管道符对齐不一致或缺少空格。

**错误**：`|------|------|` 或 `|:---:|:---:|`（缺少空格或混合对齐）

**正确**：`| :--- | :--- |`

### 7.2 Admonition 语法问题

mkdocs-material 的 admonition 语法使用中文冒号。

**错误**：`!!! note：`

**正确**：`!!! note`

### 7.3 表格空单元格问题

空单元格未保持正确的管道符对齐。

**正确**：

```markdown
| 字段 | 内容 |
| :--- | :--- |
| v0.1 | |                // 空单元格保持 `| |` 格式
```

