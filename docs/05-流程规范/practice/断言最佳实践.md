# 断言最佳实践

## 核心概述

1. **定义**：断言是对RTL设计属性的描述，本质是描述RTL时序行为**永远满足/永不发生**的属性
2. **分类**：立即断言（极少用）、**并发断言**（文档特指）
3. **定位**：白盒验证核心手段之一，属于SystemVerilog语法子集

> 注意：语法手册部分语法未在VCS仿真器完全实现（如case分支），编译可能报错

---

## 最佳实践

### 命名规范

- 统一前缀，提升可读性：
    - sequence：**seq_**
    - property：**prop_**
    - assert：**sva_**
    - cover：**cov_**

### 断言放置位置

断言可放：RTL内、package/tb/interface、**bind绑定**

- 优先：**bind绑定到所有模块实例**，不推荐仅绑定实例名(依赖作用域)

bind 的三种实现方式对比：

| 模型 | 语法示例 | 优势 | 缺点 |
| :--- | :--- | :--- | :--- |
| 绑定所有模块实例 | `bind fifo fifo_asserts pl (.*);` | 自动覆盖所有实例，无需层级限定 | 无 |
| 绑定特定实例 | `bind fifo:ul fifo_asserts asserts pl (.*);` | 可针对特定实例测试 | 需明确层级路径，易遗漏其他实例 |
| 仅绑定实例名 | `bind :ul fifo_asserts pl (.*);` | 简洁 | 依赖当前作用域，易混淆 |

绑定特定实例时，建议使用路径索引的方式。

使用bind绑定优势：

  1. 验证与设计解耦，RTL保持纯净
  2. 便于模块化、复用
  3. 兼容UVM分层验证，提升效率

### 断言编写建议

**语法建议:**

- 局部变量：**先写后读**，避免在断言中使用未初始化的局部变量
- 避免系统函数连续嵌套（如$past($rose(a))）
- 避免使用无边界时序检查窗口
- 避免多次使用`|->`/`|=>`
- 少用`not`，避免嵌套过深
- 避免简单重复设计逻辑，**反向思考**

**特殊场景:**

- 检查信号**X/Z态**：用`!==`/`===`
- 异步复位需切换时钟，建议在蕴含操作符之后切换时钟

**调试打印:**

- 用`$sampled()`打印当前时刻变量值
- 失败信息高优先级输出
- 格式化打印信息：建议断言模块内部导入`uvm_pkg`，用UVM消息分级控制日志，无需额外格式化函数
- debug定位：使用**内部局部变量辅助定位**，如循环变量等

**时间单位:**

断言模块文件内用：`$timeunit`、`$timeprecision`
（优先级高于仿真器全局设置）

**复用优化:**

- 封装通用sequence/property成库
- 用宏定义减少重复代码
- 自动化脚本生成断言

**断言屏蔽:**

- 常用：`disable iff`
- 系统函数：`$asserton`/`$assertoff`/`$assertkill`（支持按module/断言块开关）
- 数模接口建议：仿真初始关闭，时钟稳定后再开启

**寄存器模型:**

配置值尽量使用验证环境中的寄存器模型，通过`config_db`传递。

**Review:**

重点检查：覆盖完整性、时序边界、模式切换、复位/IDLE默认值
