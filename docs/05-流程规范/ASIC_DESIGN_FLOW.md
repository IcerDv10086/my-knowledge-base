# ASIC Design Flow

## 1. 背景与目标

对于消费级芯片项目，研发周期通常可抽象为三个大阶段：

1. 需求定义和架构规划
2. 芯片设计与实现
3. Tapeout 与制造、封装和测试

本文目标是总结通用的芯片设计全流程视图，帮助设计、验证、后端、测试和项目管理角色在同一套里程碑与交付标准下协同推进。

## 2. 芯片设计周期总览

### 阶段1：需求定义和架构规划

这一阶段的核心任务，是把产品目标转化为可工程化约束，并形成后续设计、验证和实现的输入。

- 需求定义：明确功能、性能、功耗、面积、成本、接口与应用场景。
- 架构规划：完成系统框图、模块划分、数据路径、时钟与复位策略、存储层级。
- 技术路径：确定工艺节点、IP 复用策略、自研与采购边界。
- 计划制定：形成**里程碑**、资源投入、风险清单及**验证总体策略**。

阶段输出建议至少包含：产品规格说明、架构规格说明、初版验证计划、项目里程碑计划。

### 阶段2：芯片设计与实现

该阶段是从逻辑功能到可制造版图的核心闭环，通常包含以下子流程。

#### 2.1 前端设计

- RTL 设计与模块集成。
- 时钟域/复位域策略落地（CDC/RDC 约束同步推进）。
- 低功耗设计意图（如多电压域、时钟门控）与实现约束协同。

#### 2.2功能验证

- 搭建验证环境，执行模块级与系统级回归。
- 通过**断言、覆盖率与关键路径场景**补强实现闭环。
- 对重点模块可引入**形式验证**提升关键属性完备性。

说明：验证不是单点活动，而是贯穿该阶段迭代收敛，通常是工时占比最高的工作。

#### 2.2.1 并行验证通道（FPGA/仿真加速）

在功能验证与后仿验证阶段，通常会并行开展 FPGA 原型验证或硬件仿真加速验证（如 Palladium 等平台）。这类工作属于预硅验证体系的并行分支，不替代仿真验证与 Tapeout Signoff，而是用于**补足纯仿真在运行速度、长时场景和软硬件协同方面的覆盖不足**。一般设置在验证部门或者软件部门下。

- FPGA 原型验证：侧重真实软件负载、长时稳定性、系统级场景覆盖与问题复现。
- 仿真加速验证：侧重大规模回归、复杂 SoC 场景和跨子系统联调效率。
- 结果使用方式：与功能验证结果共同形成验证收敛证据，并向后续签核与样片验证提供风险输入。

#### 2.3 综合与 DFT

- 结合时序约束完成逻辑综合，生成门级网表。
- 插入可测性结构（如扫描链、MBIST、JTAG 等）。
- 开展门级检查和时序一致性确认，为后端实现提供稳定输入。

#### 2.4 物理实现

- Floorplan 与电源规划。
- Place/CTS/Route 与拥塞、时序、功耗联动优化。
- 寄生参数提取与后仿分析，持续推动时序和物理质量收敛。

#### 2.5 Tapeout Signoff

- 时序签核：多模式多角（MMMC）下 setup/hold 收敛。
- 物理签核：DRC/LVS 通过，满足工艺规则。
- 可靠性签核：IR Drop、EM、SI 等满足目标。
- 可制造性签核：DFM 规则检查与修复完成。

阶段2的核心输出是：可签核的**网表、版图数据库**和完整签核报告包。

### 阶段3：Tapeout 与制造、封装和测试

该阶段把设计成果转为量产可执行方案。

- Tapeout：完成 GDSII 交付、foundry checklist 核对与版本冻结。
- 制造：晶圆厂按流程进行光刻、刻蚀、沉积等制造工序。
- 封装：完成切割、封装与成品组装。
- CP（晶圆测试）：筛选晶圆级缺陷并统计良率。
- FT（成品测试）：验证封装后器件在目标条件下的功能与性能。
- ES（样片测试）：回板后**软硬件联调**，验证真实应用场景与量产前风险。
- 量产导入：基于 CP/FT/ES 数据持续优化测试程序、参数窗口和良率表现。

## 3. 芯片类型

不同芯片类型遵循同一主流程，但技术重点不同。

- **数字芯片**：重点在 RTL 架构、验证闭环、PPA 收敛和后端签核。
- 模拟芯片：重点在电路拓扑、器件级仿真、版图匹配与后仿一致性。
- RF 芯片：重点在**高频效应**、寄生与封装协同、电磁与系统联调。
- **数模混合芯片**：重点在**跨域接口**、**联合仿真**、数字与模拟协同验证。

结合实际项目周期与资源情况，可采用分层策略：优先保障主链路（功能和签核），再逐步增强跨域联调深度。

## 4. 组织协同与项目管理

芯片项目本质是多团队并行工程，管理重点在“接口清晰、节奏统一、风险前移”。不同阶段通常会由不同团队主责，但在资源紧张或项目周期较短时，部分团队也可能同时承担多个阶段的责任。

- 阶段1：
    - 主责团队通常是系统/架构团队和产品定义团队。
    - 主要内容包括需求拆解、竞品分析、架构定义、模块边界、性能功耗预算、接口约束和初版验证策略。
    - 输出物通常包括产品规格、架构规格、项目计划、风险清单和初版验证计划。
- 阶段2：
    - 主责团队通常是 RTL 设计、验证、DFT / 综合和后端团队。
    - 主要内容包括 RTL 实现、功能验证、综合、DFT 插入、物理实现、后仿和 Tapeout Signoff。
    - 软件 / FPGA 原型团队通常并行支持长时场景、系统联调和仿真加速验证。
    - 输出物通常包括 RTL、验证报告、门级网表、版图数据库和签核报告包。
- 阶段3：
    - 主责团队通常是测试团队、产品工程团队和软件团队。
    - 主要内容包括 Tapeout 交付、晶圆制造、封装、CP、FT、ES 样片测试和量产导入。
    - 输出物通常包括测试程序、样片问题闭环、良率数据和量产导入结论。
- 角色协同：
    - 系统/架构团队负责需求拆解、架构定义、功能边界、性能功耗预算与接口约束。
    - RTL 设计团队负责将架构落地为可综合实现，并保证模块间接口与功能行为一致。
    - 验证团队负责验证策略、验证环境、回归收敛、覆盖率和关键场景闭环。
    - DFT / 综合团队负责网表生成、可测性结构插入和面向量产测试的实现准备。
    - 后端团队负责布局布线、时钟树、电源规划、寄生提取和物理签核。
    - 软件 / FPGA 原型团队负责原型平台、系统联调、长时运行和真实场景问题暴露。
    - 测试团队负责 CP、FT、测试程序、量产测试策略和良率分析。
    - 产品工程团队负责样片问题闭环、测试导入和量产推进。
    - 项目经理或项目技术负责人负责节奏统筹、风险跟踪、评审组织和变更控制。
- 监督机制：各技术负责人对本领域结果负责，项目经理对整体节奏负责，关键节点通过评审会或签核会统一放行。
- 里程碑管理
- 变更控制：需求变更、RTL 变更和测试变更应统一进入 ECO 流程，并重新评估对后续里程碑的影响。
