# LSF 原理速记

## 1. 调度核心概念

- `job`：提交给集群的任务。
- `queue`：任务进入的队列，决定调度策略和资源上限。
- `slot`：可并行调度的执行单元，通常与 CPU 核数强相关。
- `host`：执行节点。

工程上常用近似：一个计算密集型 job 往往消耗一个或多个 slot。

## 2. 调度逻辑（简化）

1. 用户提交 job（带资源需求）。
2. 调度器根据队列策略筛选候选节点。
3. 判断资源是否满足（CPU、内存、主机限制、依赖关系）。
4. 满足则启动，不满足则排队。

## 3. 资源需求与排队关系

- 资源申请越大，排队时间通常越长。
- 依赖关系（`-w`）会让 job 在前序完成前保持 PEND。
- 指定主机（`-m`）会收窄调度范围，可能导致等待变长。

## 4. 常见状态

- `PEND`：排队中。
- `RUN`：运行中。
- `DONE`：成功结束。
- `EXIT`：异常退出。

## 5. 实战建议

1. 资源按需申请，不要盲目高配。
2. 使用统一命令模板，保证可复现。
3. 回归任务建议绑定日志命名规范（含 `%J`）。
4. 大规模回归前先做小样本试跑，确认资源画像。
