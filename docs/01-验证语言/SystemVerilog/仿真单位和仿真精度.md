# SystemVerilog 仿真单位与仿真精度

## 1. 基本概念

- `time`：64 位无符号整数，适合离散时间计数。
- `realtime`：64 位浮点类型，适合需要小数时间精度的场景。
- 时间字面量示例：`2.1fs`、`5ns`、`1us`（数字与单位之间不能有空格）。

在代码中：

- `#1` 表示延迟一个“仿真单位”（time unit）。
- 仿真精度（time precision）决定仿真器最小时间步进。

## 2. 声明方式与优先级

### 2.1 声明方式

- Verilog 传统方式：``timescale``。
- SystemVerilog 推荐方式：`timeunit` + `timeprecision`。

示例：

```systemverilog
timeunit 1ns;
timeprecision 1ps;
```

### 2.2 生效范围

- 作用于最基本编译单元（如 module、interface、program、package、class）。
- 不同编译单元可以有不同时间单位与精度。

### 2.3 常见优先级（工程视角）

1. 命令行覆盖参数（如工具提供的 `override_timescale`）。
2. `timeunit/timeprecision`。
3. ``timescale``。

## 3. 时间函数与显示

- `$time`：返回离散整数时间。
- `$realtime`：返回浮点时间。
- `$timeformat`：控制日志时间打印格式。

建议：

- 项目内统一 `$timeformat`，便于日志检索。
- 涉及亚单位边界检查时优先使用 `$realtime`。

## 4. VCS 排查建议

- 使用 `-diag timescale` 在编译阶段输出各模块时间单位/精度。
- 排查顺序：
  1. 看命令行是否覆盖。
  2. 看模块内是否声明 `timeunit/timeprecision`。
  3. 看 ``timescale`` 是否被后续文件改写或被 ``resetall`` 清除。

## 5. 最佳实践

- 每个关键编译单元都显式声明时间配置，避免隐式继承。
- 项目尽量统一主时间单位（常见为 `1ns`）。
- 后仿精度不宜过粗（可能掩盖时序问题），也不宜过细（严重拖慢性能）。
- 在 TB 中仅使用“满足验证目标的最细精度”，避免无意义的超高精度。
- 建议维护一份时间配置清单，在前仿/后仿入口自动检查。
