# SystemVerilog 调度语义

## 1. 背景

SystemVerilog 是并发事件驱动语言。理解调度语义的目标是回答三个问题：

1. 某个语句在什么时间区域执行。
2. 多个进程并发时哪些顺序可预测、哪些不可预测。
3. 竞争条件是如何产生的，以及如何规避。

## 2. 事件驱动模型

- 仿真由“时间片（time slot）+ 区域（region）”组成。
- 事件分为：
    - 更新事件：修改网表/变量值。
    - 评估事件：触发进程执行、产生新事件。
- 仿真时间只前进不回退。

## 3. 分层事件区域

常见执行顺序可概括为：

`Preponed -> Active -> Inactive -> NBA -> Observed -> Reactive -> Re-NBA -> Postponed`

完整标准包含 17 个区域。工程上可关注三组：

- 设计核心区：`Active / Inactive / NBA`。
- 断言观察区：`Observed`。
- 验证反应区：`Reactive / Re-NBA`。

## 4. 关键执行规则

### 4.1 确定性部分

- 同一 `begin...end` 内语句按源码顺序执行。
- 同一进程内的 NBA 入队顺序可预测。

### 4.2 非确定性部分

- 同一区域内多个并发进程的先后顺序通常不保证。
- 无显式时序控制的并发语句可能交织执行。

### 4.3 竞争条件

当“读值”和“写值”发生在同一时间片、且区域次序处理不当时，会产生竞争。

规避建议：

- TB 与 DUT 交互优先用 clocking block。
- 避免在同一时间片混用阻塞赋值与采样逻辑。

## 5. 赋值语句与调度关系

- 连续赋值：输入变化后在活动区域触发更新。
- 阻塞赋值（`=`）：当前流程立即生效（可能进入 Inactive/未来时间片）。
- 非阻塞赋值（`<=`）：计算当前值，更新在 NBA/Re-NBA 区域提交。
- `assign/force` 等过程连续赋值：也会通过调度队列驱动网络。

## 6. PLI 回调常见映射

- `cbAfterDelay`：常用于 `Pre-Active` 前后控制。
- `cbReadWriteSynch`：常见于 `Pre-NBA/Post-NBA`。
- `cbReadOnlySynch`：常用于 `Postponed` 只读观察。

## 7. 实战建议

1. 出现“偶发错误”时，先按区域分析而不是先怀疑随机种子。
2. 统一约定 TB 驱动与采样相位，减少 race。
3. 在关键接口加断言，锁定“值何时稳定、何时被采样”。
