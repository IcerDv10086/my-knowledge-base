# 功能覆盖率

## 核心概念

功能覆盖率（Functional Coverage）是验证完备性的量化指标，核心在于**采样点选取**与**采样方法选择**，用于衡量设计功能被验证的充分程度。

- **定义位置**：可定义在 `module`、`interface`、`class` 中
- **核心组件**：`covergroup`（覆盖组）、`coverpoint`（覆盖点）、`covercross`（交叉覆盖）
- **应用目标**：确保设计的所有功能场景都被测试覆盖

## 使用流程

功能覆盖率的使用分为三个核心步骤：

1. **定义阶段**：声明 `covergroup`，包含 `coverpoint` 和 `covercross`
2. **实例化阶段**：声明覆盖组变量，在 `initial` 块或 `class::new()` 中实例化
3. **采样阶段**：在仿真过程中触发 `sample()` 或覆盖组自带的采样事件进行采样

## 核心语法结构

### covergroup（覆盖组）

`covergroup` 是功能覆盖率的基本容器，可包含多个 `coverpoint` 和 `covercross`。

**关键特性**：

- 内置 `sample()` 方法，支持重载和参数传递（`ref`、缺省值、名字传参）
- 可指定采样触发事件（如 `@(posedge clk)`、`@(event)`）
- IEEE 2012 支持阻塞事件采样，但 **VCS 等主流工具未实现**

**Class 中的嵌入式覆盖组示例**：

```systemverilog
class A0;
    int sub_x;
endclass

class A1;
    bit [7:0] x;
    A0 a0_obj;

    // 覆盖组定义，在 x 变化时触发采样，此处算覆盖组的声明
    covergroup cv_test0 @(x);
        coverpoint a0_obj.sub_x;
    endgroup: cv_test0

    function new();
        a0_obj = new();
        cv_test0 = new();  // 必须显式实例化
    endfunction
endclass
```

### coverpoint（覆盖点）

`coverpoint` 用于覆盖单个变量或表达式，是最基本的覆盖单元。

**关键特性**：

- 覆盖单个变量/表达式
- 支持**条件保护表达式**（满足条件才采样）
- 可定义多种类型的 bins

**通用的仓类型**可分为状态仓和转换仓两大类。

**状态仓（State Bins）**：

- 与值域集合相关，统计特定值的出现次数
- 值域写法：
    - `{}` 表示集合，逗号分隔多个值
    - `$` 表示最大值，`:` 表示区间
    - `default` 表示未显式声明的所有值

**转换仓（Transition Bins）**：

- 与值变化相关，适合信号跳变检查，使用`(A=>B)` 表示 A 转换为 B，多个转换间使用`,`分割
- 运算符：
    - `[*]`：连续重复运算符
    - `[->]`：跟随重复运算符
    - `[=]`：非连续重复运算符

**特殊仓类型**：

| 类型 | 关键字 | 说明 |
| :--- | :--- | :--- |
| 通配符仓 | `wildcard bins` | `?` 代表 0/1/z |
| 忽略仓 | `ignore bins` | 对应值域不观测，不可与 `default` 同用 |
| 非法仓 | `illegal bins` | 击中时报错，提示设计/仿真问题 |

这些特殊仓可以用作状态仓和转换仓。

**示例代码**：

```systemverilog
covergroup bus_cov;
    // 状态仓示例：覆盖地址范围
    addr: coverpoint addr_bus {
        bins low_addr = {[0:127]};
        bins mid_addr = {[128:255]};
        bins high_addr = {[256:$]};
        wildcard bins temp = {4'b?11??}; //注意wildcard 只是
        illegal_bins illegal = {1};
        ignore_bins reserved = {32'hFF00_0000, 32'hFF00_0001};
    }

    // 转换仓示例：检测状态机转换
    state: coverpoint fsm_state {
        bins trans1 = (IDLE => ACTIVE => DONE);
        bins trans2 = (IDLE [->2] => ACTIVE);  // 非连续重复
    }
endgroup
```

### covercross（交叉覆盖）

`covercross` 用于描述多变量交互场景，验证变量组合的覆盖情况。

**关键特性**：

- 只能使用**变量名/覆盖点**，不支持表达式
- 支持条件保护表达式
- 默认生成自动交叉仓；用户显式定义仓会自动排除对应自动仓
- 高阶筛选：`binsof...intersect...`、`with`、布尔运算

**示例代码**：

```systemverilog
covergroup cross_cov;
    cp_op: coverpoint opcode;
    cp_mode: coverpoint mode;
    
    // 交叉覆盖：操作码与模式的组合
    cross_op_mode: cross cp_op, cp_mode {
        // 只关注特定操作码范围的交叉
        bins valid_cross = binsof(cp_op) intersect {[0:7]} 
                          && binsof(cp_mode) intersect {1, 3};
        ignore_bins invalid = binsof(cp_mode) intersect {0};
    }
endgroup
```

## 覆盖选项（option / type_option）

### option（实例级选项）

`option` 用于配置**单个覆盖组实例以及内部的覆盖点和交叉覆盖**的行为：

| 选项 | 说明 | 默认值 |
| :--- | :--- | :--- |
| `name` | 指定覆盖组实例名称，未指定时工具自动生成唯一名称 | unique name |
| **`weight`** | 在 covergroup 层级设置时，指定该实例对整体覆盖率的权重；在 coverpoint/cross 层级设置时，指定该覆盖点/交叉覆盖对所属覆盖组的权重，必须为**非负整数** | 1 |
| `goal` | 覆盖率目标（100 = 满覆盖），适用于覆盖组实例、覆盖点或交叉覆盖 | 100 |
| `comment` | 报告中显示的注释，保存在覆盖率数据库中 | "" |
| `at_least` | 每个仓至少击中的次数，少于该次数不算覆盖 | 1 |
| **`auto_bin_max`** | 未显式定义 bins 时，**coverpoint** 自动创建的最大仓数 | 64 |
| **`cross_num_print_missing`** | 保存并打印到覆盖率报告中的未覆盖交叉仓数量 | 0 |
| **`cross_retain_auto_bins`** | **为 true 时，自动生成的交叉仓在用户定义交叉仓后仍保留**；为 false 时，用户定义交叉仓会移除所有自动生成仓 | 1 |
| `detect_overlap` | 为 true 时，若两个仓的值域（或转换列表）有重叠则发出警告 | 0 |
| `per_instance` | 为 true 时，每个实例贡献整体覆盖率信息并保存到数据库；为 false 时，实现无需保存实例特定信息 | 0 |
| `get_inst_coverage` | 仅在 `merge_instances` 类型选项设置时生效，启用 `get_inst_coverage` 内置方法的实例级覆盖率追踪；为 false 时，返回值等于 `get_coverage` 的返回值 | 0 |

在SystemVerilog 3.1a（2004）语法中，可以使用 **`cross_auto_bin_max`** 用于指定 covercross 自动创建的交叉仓数量，用于**限制自动生成的交叉仓的数量，防止组合爆炸**。

但在2007以后的版本中废弃了，属于非标用法，但是目前大部分EDA工具仍然支持此选项。个人建议使用最新的`cross_retain_auto_bins`选项替换。

### type_option（类型级选项）

`type_option` 用于配置**整个覆盖组类型**的默认行为，对该类型的所有实例生效：

| 选项 | 说明 | 默认值 |
| :--- | :--- | :--- |
| `weight` | 在 covergroup 层级设置时，指定该类型对整体累积（或类型）覆盖率的权重；在 coverpoint/cross 层级设置时，指定该覆盖点/交叉覆盖对所属覆盖组类型累积覆盖率的权重，必须为非负整数 | 1 |
| `goal` | 指定覆盖组类型、覆盖点或交叉覆盖的目标覆盖率 | 100 |
| `comment` | 与覆盖组类型、覆盖点或交叉覆盖关联的注释，保存在覆盖率数据库中并包含在覆盖率报告中 | "" |
| `strobe` | 为 true 时，所有采样在时间槽末尾发生，类似于 `$strobe` 系统任务 | 0 |
| **`merge_instances`** | 为 true 时，累积（或类型）覆盖率通过合并所有实例的覆盖率（作为**并集**）计算；为 false 时，类型覆盖率作为所有实例的加权平均值计算 | 0 |
| `distribute_first` | 为 true 时，指示工具在应用 `with_covergroup_expression` 之前先执行值到仓的分布 | 0 |
| `real_interval` | 指定实数值范围区间的宽度，分布在多个仓中 | 1.0 |

需要指出的是，`distribute_first`、`real_interval` 为2023版本新增选项。

在 SV 2017 及更早版本中，coverpoint 的采样顺序固定，是：

1. 先执行 with 条件过滤（(expr)）
2. 再把通过过滤的值分配到 bins 中

但当 distribute_first = 1 时，顺序会反转：

1. 先把采样值分配到 bins（按 auto_bin_max、bins 定义）
2. 再用 with 条件过滤掉不满足条件的 bins / 采样点

SV对于**实数**数据类型（real、shortreal）的功能覆盖率的支持很弱，如

1. 无法像整数一样，利用auto_bin_max进行数据均分
2. 手动定义 bins， 存在**浮点精度误差**：eg. `0.1+0.2 != 0.3`

而当定义 `real_interval` 时，把 real 变量的取值范围自动划分为等宽区间仓，每个仓的宽度为 `real_interval`。示例如下：

```systemverilog
//场景：覆盖一个 real 类型的温度传感器输出，自动生成的仓：[0.0, 0.5), [0.5, 1.0), ..., [9.5, 10.0)。
covergroup cg_real;
  real temp;
  option.real_interval = 0.5; // 自动仓宽度 0.5
  coverpoint temp {
    option.auto_bin_max = 20; // 最多生成 20 个仓，覆盖 0~10℃
  }
endgroup
```

## 采样方法

功能覆盖率通过事件触发采样，核心方法包括：

### @clocking_event

最常见且通用的方法，指定时钟与采样事件，如 `@(posedge clk)`。在时钟上升沿采样数据。

### sample() 方法

`sample()` 是内置方法，一般不需要显式声明，在以下情况自动或手动调用：

```systemverilog
covergroup my_cov;
    coverpoint data;
endgroup

my_cov cov_inst = new();

// 手动调用采样
cov_inst.sample();

// 带参数的 sample() 方法
covergroup param_cov with function sample(input int mask);
    coverpoint irq_data&mask;
endgroup
```

### start() / stop() 方法

用于手动控制覆盖组的采样时间段：

```systemverilog
cov_inst.start();   // 开始采样
// ... 仿真代码 ...
cov_inst.stop();    // 停止采样
```

需要指出语法手册中`@@blocking_event_expression` 在新思的VCS仿真工具中不支持。

## 使用场景与个人实践

- 顶层 DUT 接口信号覆盖
    - **应用场景**：对难以完全 toggle 的接口信号，覆盖典型值和边界条件。

- 测试用例 + 设计内部信号结合
    - 围绕设计 feature 定义覆盖点
    - 用开关控制采样，对应测试用例使能才采集
    - 用于内部信号的双重验证

- 测试用例随机化结果监测
