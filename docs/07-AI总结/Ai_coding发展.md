# AI-coding发展总结

## 发展主线

2023 年，大语言模型（LLM）爆发。

2025 年以来，AI-coding 从“对话式补全”快速走向“任务式协作”。早期重点是提升单点生成能力，随后转向工具调用、上下文管理与工程可控性。到现在，行业共识已经从“能写代码”升级为“能稳定交付、可回归验证、可规模复用”。因此，**真正的分水岭不在模型参数，而在工程体系是否闭环**。

## RAG（Retrieval-Augmented Generation）

检索增强生成。

常用的生成向量的方式，但目前比较热门的反而是无向量，通过index来检索。适用于中小型的任务。

## MCP

本质：把模型与**外部工具、数据源、执行环境**连接成标准接口。

## PROMT

Prompt（这里你写的是 PROMT）这块，2025 年后最大的变化是：它不再只是“怎么问得漂亮”，而是“怎么把任务说清楚”。
一句有效的 Prompt，最好同时说清目标、边界、输出格式和验收标准。
说白了，Prompt 越像任务说明书，AI 的输出就越稳定。

## SKILLS

Skills = “可复用的工作套路”。
比如某类任务你每次都要重复同样步骤，那就应该沉淀成一个固定能力模块，而不是每次从零对话。
这样做的好处很明显：结果更稳、协作更顺，也更容易把个人经验变成团队资产。

## SOLO && VIBE_CODING

Solo 模式的核心不是“单打独斗”，而是“一个人带着 AI 完成一整条链路”。
以前要多人配合的需求梳理、编码、测试、文档，现在很多场景一个人就能先跑通。
它特别适合快速试错，但前提是自己要守住质量底线，不然很容易快是快了，后面返工更多。

Vibe Coding 我理解成一种高频来回的协作节奏：先快速做出可运行版本，再不断打磨。
这种方式在原型期非常爽，灵感来了马上就能落地。
但它也有风险，最常见的是结构越写越散，所以要定期停下来做整理和收敛。

## HARNESS ENGINEERING

Harness Engineering 可以简单理解成：给 AI 产出配一套“自动验收系统”。
你不能只看它这次写得像不像，还要看下次改动会不会把旧功能搞坏。
所以要有样例集、回归测试和评测基线。没有这层，AI 带来的效率很容易是短期的；有了这层，效率才会变成稳定产能。
